2. GIT CONFIGURATION & REPOSITORY LEAKAGE RISK
----------------------------------------------------------------------
Critical Finding: ABSENCE OF `.gitignore` FILE IN PROJECT ROOT
- The root directory lacks a `.gitignore` file.
- Impact:
  If an operator initializes git (`git init`) or runs `git add .`, the following
  highly sensitive, local-only files will be staged and committed:
  * `.env` (Containing administrative security tokens)
  * `backend/database.sqlite` (Containing all real customer PII, debts, and sales)
  * `backend/backups/*.sqlite` (Complete historical customer and financial snapshots)
  * `node_modules/` (Bloating repository)
- Remediation:
  Create a comprehensive `.gitignore` immediately:
  ```gitignore
  .env
  *.sqlite
  *.db
  backend/backups/
  node_modules/
  dist/
  serviceAccountKey.json
  *.log
  ```

----------------------------------------------------------------------
3. RUNTIME CONFIGURATION AUDIT
----------------------------------------------------------------------
1. Environment Variable Gating:
   - `ALLOW_DB_RESET`:
     * Currently set to `true` in `.env`.
     * If left as `true` in production, any local caller knowing or guessing the token
       can wipe the business database.
     * Recommendation: Set `ALLOW_DB_RESET=false` in all real production deployments.
2. Port and Host Configuration:
   - Server listens on port `7860` without explicit host binding, exposing APIs to LAN.
   - Add `HOST=127.0.0.1` in `.env` to restrict execution to the local counter terminal.
3. Node.js Environment (`NODE_ENV`):
   - Currently undefined or defaults to development mode.
   - Setting `NODE_ENV=production` optimizes Express performance and suppresses verbose error strings.
