1. MODULE PURPOSE
----------------------------------------------------------------------
The Inventory module provides complete catalog management, physical stock
tracking, branch-level stock segregation (Shop 1 vs. Shop 2), inter-shop stock
transfers, supplier procurement linkage, and automated duplicate product
reconciliation. It acts as the physical inventory authority for the POS
checkout engine, billing returns, and supplier receiving workflows.

----------------------------------------------------------------------
2. FEATURES FOUND
----------------------------------------------------------------------
- Product creation with Name, Size, Unit, Stock, Purchase Price, Sale Price,
  Shop ID, and Supplier link.
- Automated purchase generation when creating products with initial stock and
  a linked supplier.
- Product updating (editing name, size, unit, category, purchase/sale prices).
- Product deletion with database record purge.
- Multi-shop branch switching (Shop 1 vs Shop 2 inventory context).
- Inter-shop stock transfer with automatic target SKU creation or incrementation.
- Inter-shop stock transfer audit history logging.
- Insufficient stock overdraft prevention guards.
- Negative quantity and price validation guards.
- Startup duplicate reconciler merging identical (shopId::name::size::unit) entities.
- Low stock visual indicators (green >= 10, red < 10).
- Product search by name, size, category, and SKU.

----------------------------------------------------------------------
3. ACTUAL WORKFLOW
----------------------------------------------------------------------
1. Product Creation:
   User clicks "Add Product" -> Enters Name, selects Supplier (optional), enters
   Size, Stock, Cost Price, Sale Price -> If stock > 0 and supplier selected,
   the backend automatically creates a linked purchase record in `purchases` table
   and updates the supplier Accounts Payable balance.
2. Inter-Shop Stock Transfer:
   User clicks "Transfer Stock" on a product row -> Selects Target Shop -> Enters
   quantity -> System validates `quantity <= available stock` -> Source stock
   is decremented -> If product already exists in target shop (matching SKU or
   Name+Size+Unit), target stock increments; otherwise a new product record is
   created in target shop -> An entry is written to `stockTransfers`.
3. Stock Consumption & Returns:
   - Billing Checkout: Sales automatically decrement physical inventory.
   - Billing Return: Return orders increment physical inventory.
   - Purchases: Procurement shipments increment physical inventory.

----------------------------------------------------------------------
4. UI FLOW
----------------------------------------------------------------------
- Component: Mounted at `currentPage === 'products'`.
- Header: Location selector (Shop 1 / Shop 2 toggle), Search input, "Add Product" button.
- Main Table: Displays Product Name, Size & Unit, Stock (color-coded badge), Sale Price,
  and Action menu button (Ellipsis icon).
- Action Dropdown: "Edit Product", "Delete Product".
- Add/Edit Modal: Clean form with inputs for Name, Supplier dropdown, Size, Stock,
  Cost Price, Sale Price. Cancel and Submit buttons. Shows blue banner informing user
  that an initial purchase will be auto-created if stock > 0 and supplier selected.
- Transfer Modal: Source product summary, Target Shop selector, Transfer Quantity input.

----------------------------------------------------------------------
5. API FLOW
----------------------------------------------------------------------
- GET /api/products -> Fetches array of all product records from SQLite document store.
- POST /api/products -> Validates name, stock (non-negative), prices (non-negative).
  Inserts row into `products`. If stock > 0 and supplierId present, inserts into
  `purchases`, updates `suppliers` balance and totalPurchased, and optionally writes
  to `supplierPayments` if paidAmount > 0. Returns HTTP 201 with product payload.
- PUT /api/products/:id -> Updates product attributes while stripping undefined fields.
  Returns HTTP 200 with updated object.
- DELETE /api/products/:id -> Removes product from `products` table. Returns HTTP 200.
- POST /api/products/transfer -> Validates source product exists and has sufficient stock.
  Decrements source product stock. Finds or creates target shop product. Increments
  target product stock. Inserts record into `stockTransfers`. Returns HTTP 200.
- GET /api/stock-transfers -> Returns array of all inter-shop transfer records.

----------------------------------------------------------------------
6. DATABASE TABLES USED
----------------------------------------------------------------------
- `products`: Primary table storing product entities.
- `stockTransfers`: Audit log of inter-shop transfers.
- `purchases`: Automatically written if product created with supplier and initial stock.
- `suppliers`: Accounts payable balance updated if product created with supplier.
- `supplierPayments`: Written if upfront cash paid during initial product creation.

----------------------------------------------------------------------
7. DATABASE FIELDS INVOLVED
----------------------------------------------------------------------
`products` table (SQLite schema: `id TEXT PRIMARY KEY, data TEXT`):
- `id`: UUID string (e.g., 'f1d0b3e7-b2eb-4fbf-88ed-63f7a6264ba7')
- `data.name`: String, trimmed product name.
- `data.category`: String (optional).
- `data.size`: String (e.g., '6x3 ft', 'Standard').
- `data.unit`: String ('Piece', 'Set', 'Meter', etc.).
- `data.stock`: Number (integer or float for meters/kg).
- `data.purchasePrice`: Number (cost price).
- `data.retailPrice` / `data.salePrice`: Number.
- `data.shopId`: String ('shop-1' or 'shop-2').
- `data.supplierId`: String (optional UUID).
- `data.createdAt`: Integer Unix timestamp (ms).

`stockTransfers` table (SQLite schema: `id TEXT PRIMARY KEY, data TEXT`):
- `id`: UUID string.
- `data.sourceProductId`: UUID string.
- `data.targetProductId`: UUID string.
- `data.productName`: String.
- `data.quantity`: Number.
- `data.sourceShopId`: String ('shop-1').
- `data.targetShopId`: String ('shop-2').
- `data.date`: Integer Unix timestamp (ms).

----------------------------------------------------------------------
8. DATABASE RELATIONSHIPS
----------------------------------------------------------------------
- `products.id` -> referenced by `sales.items[].productId` (1:N)
- `products.id` -> referenced by `purchases.items[].productId` (1:N)
- `products.id` -> referenced by `stockTransfers.sourceProductId` & `targetProductId`
- `suppliers.id` -> referenced by `products.supplierId` (1:N)
* Note on Schema Design: Because the SQLite database uses a document-store pattern
  (`data TEXT` storing JSON), relationships are managed at the application/middleware
  level without foreign key constraints enforced by SQLite DDL.

----------------------------------------------------------------------
9. CREATE / UPDATE / DELETE OPERATIONS
----------------------------------------------------------------------
- CREATE:
  - Validates non-empty `name`, `stock >= 0`, `purchasePrice >= 0`, `retailPrice >= 0`.
  - Atomically writes to `products`.
  - Conditional cross-table writes to `purchases`, `suppliers`, and `supplierPayments`.
- UPDATE:
  - Merges incoming payload with existing record via `stripUndefined`.
  - Preserves immutable fields such as `createdAt`.
- DELETE:
  - Executes `DELETE FROM products WHERE id = ?`.
  - Note: Does not perform cascading deletes on historical sales/purchases.

----------------------------------------------------------------------
10. BUSINESS LOGIC
----------------------------------------------------------------------
- Open / Flexible Furniture Pricing: Retail price defaults to 0 or open price,
  accommodating counter negotiation typical of high-ticket furniture retail.
- Automated Procurement Invoicing: Eliminates double entry when stocking new items
  from a known supplier.
- Branch Isolation: Products in Shop 1 cannot be sold in Shop 2 without an explicit
  inter-shop stock transfer.
- Case-Insensitive Duplicate Key: Reconciler defines a product identity as:
  `${shopId}::${name.toLowerCase()}::${size.toLowerCase()}::${unit.toLowerCase()}`.

----------------------------------------------------------------------
11. CALCULATIONS
----------------------------------------------------------------------
- Initial Stock Cost:
  $$\text{Total Cost} = \text{Stock} \times \text{PurchasePrice}$$
- Remaining Supplier Debt:
  $$\text{Remaining Debt} = \text{Total Cost} - \text{PaidAmount}$$
- Inter-Shop Stock Transfer:
  $$\text{New Source Stock} = \text{Source Stock} - \text{TransferQty}$$
  $$\text{New Target Stock} = \text{Target Stock} + \text{TransferQty}$$

  from the invoice snapshot.
