2. HTTP METHOD VALIDATION & ROUTE DISPATCH
----------------------------------------------------------------------
Express router handles strict path matching.
- Unknown methods (e.g. `PATCH /api/products/:id`) return `HTTP 404 Cannot PATCH /api/products/...`.
- `OPTIONS` pre-flight requests are handled by CORS middleware.
- Head requests are supported on static assets.

----------------------------------------------------------------------
3. MASS ASSIGNMENT & UNSAFE FIELD CONTAMINATION
----------------------------------------------------------------------
1. Mitigated Routes:
   - `PUT /api/customers/:id`: Explicitly strips `{ balance, totalPurchased, totalPaid }`.
   - `PUT /api/suppliers/:id`: Explicitly strips `{ balance, totalPurchased, totalPaid }`.
   - `POST /api/supplier-payments`: Hardcodes `isImmediate: false, purchaseId: null`.
2. Remaining Mass Assignment Exposures:
   - `PUT /api/products/:id`: Merges `req.body` directly without schema allowlisting.
     A caller can inject arbitrary metadata or override `shopId`.
   - `POST /api/expenses`: Merges `req.body` directly with `createdAt: Date.now()`.

----------------------------------------------------------------------
4. INPUT VALIDATION & BOUNDARY INTEGRITY
----------------------------------------------------------------------
- Strong Validations Present:
  * In `POST /api/sales`: Line item quantity must be $> 0$; prices must be $\ge 0$.
  * In `POST /api/products`: Stock and purchase/retail prices must be non-negative.
  * In `POST /api/products/transfer`: Quantity must be $> 0$; available stock verified.
  * In `POST /api/supplier-payments`: Positive amount check, zero-balance lock, and overpayment guard.
  * In `POST /api/purchases`: Non-empty items array, positive total, upfront paid amount $\le$ total.
- Missing Validations:
  * `POST /api/sales`: Discrepancy check between items sum and `total`.
  * `PUT /api/products/:id`: Non-negative bounds on stock and prices.
  * `POST /api/expenses`: Positive amount check.
  * `POST /api/payments`: Customer debt upper bound check.

----------------------------------------------------------------------
5. EXCEPTION HANDLING & INFORMATION LEAKAGE
----------------------------------------------------------------------
All API routes wrap logic in `try { ... } catch (error) { res.status(500).json({ error: error.message }); }`.
- Strengths:
  * Server does NOT expose raw V8 stack traces or filesystem paths to callers.
  * Always returns standard JSON (`{ error: ... }`).
- Weaknesses:
  * `error.message` can leak underlying SQLite schema errors (e.g. `"SQLITE_BUSY: database is locked"` or `"no such table: ..."`).
