1. MODULE PURPOSE
----------------------------------------------------------------------
The Suppliers module manages wholesale vendor profiles, procurement shipments
and stock intake, Accounts Payable liability tracking, upfront procurement cash
disbursements, subsequent vendor debt settlements, and financial payment guardrails
including zero-balance lockouts and overpayment prevention.

----------------------------------------------------------------------
2. FEATURES FOUND
----------------------------------------------------------------------
- Supplier profile directory (`name`, `contactPerson`, `phone`, `email`, `address`).
- Supplier editing and deletion.
- Procurement Receiving / Purchase Invoicing (`POST /api/purchases`):
  - Line items, quantities, cost prices, and item totals.
  - Automatic physical inventory incrementation in targeted showroom/warehouse.
  - Automatic vendor liability accrual (`totalAmount - paidAmount`).
  - Automatic upfront disbursement recording in `supplierPayments`.
- Supplier Payment Accounting (`POST /api/supplier-payments`):
  - Installment disbursements against outstanding accounts payable.
  - Reduces vendor debt balance; increments vendor `totalPaid`.
- Zero-Balance Payment Lock:
  - UI button hard-disabled with tooltip when vendor balance is $\le 0$.
  - API strictly rejects payment submissions when balance is 0 (`HTTP 400`).
- Overpayment Guard:
  - API strictly rejects disbursements exceeding outstanding supplier dues (`HTTP 400`).
- Non-positive payment amount rejection (`HTTP 400`).
- Non-existent supplier ID rejection (`HTTP 404`).

----------------------------------------------------------------------
3. ACTUAL WORKFLOW
----------------------------------------------------------------------
1. Vendor Profile Creation:
   User clicks "Add Supplier" -> Enters Company Name, Contact Person, Phone, Email,
   and Address -> Submits -> System creates record in `suppliers` table with
   `balance: 0`, `totalPurchased: 0`, `totalPaid: 0`.
2. Procurement Receiving:
   User opens Purchases -> Selects Supplier, target branch (Shop 1 / Shop 2), adds
   items with received quantities and negotiated cost prices, enters upfront cash
   paid -> System saves purchase record, increases physical stock of all received
   products, increments supplier Accounts Payable balance by remaining cost, and
   logs cash paid into `supplierPayments`.
3. Subsequent Vendor Settlement:
   Operator opens Supplier profile -> System evaluates supplier balance. If balance > 0,
   "Pay Supplier" is enabled. Operator enters amount, payment method (Cheque/Bank/Cash),
   notes -> System reduces supplier balance and records payment in `supplierPayments`.

----------------------------------------------------------------------
4. UI FLOW
----------------------------------------------------------------------
- Component: Mounted at `currentPage === 'suppliers'`.
- Header: Vendor search bar, "Add Supplier" primary button.
- Supplier Table/Cards: Displays Supplier Name, Contact Person, Phone, Email,
  Total Invoiced Purchases, Total Paid, and Current Accounts Payable Balance
  (red badge if balance > 0, green if 0).
- Action Buttons:
  - "Pay Supplier": Disabled with styling `opacity-40 cursor-not-allowed` and tooltip
    `"No pending dues to pay"` when balance is $\le 0$. Enabled when balance > 0.
  - "Edit Supplier", "Delete Supplier".
- Payment Modal: Shows current pending balance, payment amount input, payment method
  dropdown, and notes.

----------------------------------------------------------------------
5. API FLOW
----------------------------------------------------------------------
- GET /api/suppliers -> Fetches array of all supplier JSON documents.
- POST /api/suppliers -> Validates name is non-empty string. Initializes financial
  counters (`balance: 0, totalPurchased: 0, totalPaid: 0`). Returns HTTP 201.
- PUT /api/suppliers/:id -> Updates supplier contact details. Returns HTTP 200.
- DELETE /api/suppliers/:id -> Deletes supplier record. Returns HTTP 200.
- POST /api/purchases -> Creates purchase invoice, updates physical product stock,
  updates supplier balance, and logs upfront payment. Returns HTTP 201.
- POST /api/supplier-payments -> Validates supplier exists, amount > 0, balance > 0,
  and amount <= balance. Decrements supplier balance and writes to `supplierPayments`.
  Returns HTTP 201.

----------------------------------------------------------------------
6. DATABASE TABLES USED
----------------------------------------------------------------------
- `suppliers`: Primary table storing vendor identities and Accounts Payable balances.
- `purchases`: Records incoming stock shipments and vendor invoice details.
- `supplierPayments`: Records all cash/bank disbursements to suppliers.
- `products`: Physical stock incremented upon receiving purchase items.

----------------------------------------------------------------------
7. DATABASE FIELDS INVOLVED
----------------------------------------------------------------------
`suppliers` table (`id TEXT PRIMARY KEY, data TEXT`):
- `id`: UUID string.
- `data.name`: String, vendor trade name.
- `data.contactPerson`: String.
- `data.phone`: String.
- `data.email`: String.
- `data.address`: String.
- `data.balance`: Number (net outstanding accounts payable liability).
- `data.totalPurchased`: Number (cumulative procurement shipments).
- `data.totalPaid`: Number (cumulative disbursements).
- `data.createdAt`: Unix timestamp (ms).

`purchases` table (`id TEXT PRIMARY KEY, data TEXT`):
- `id`: UUID string.
- `data.supplierId`: UUID string.
- `data.supplierName`: String.
- `data.totalAmount`: Number.
- `data.paidAmount`: Number.
- `data.remainingAmount`: Number.
- `data.shopId`: 'shop-1' | 'shop-2'.
- `data.items`: `[{ productId, name, quantity, costPrice, total }]`.
- `data.createdAt` & `data.date`: Unix timestamp (ms).

`supplierPayments` table (`id TEXT PRIMARY KEY, data TEXT`):
- `id`: UUID string.
- `data.supplierId`: UUID string.
- `data.amount`: Number.
- `data.method`: 'Cash' | 'Cheque' | 'Bank Transfer'.
- `data.note`: String.
- `data.createdAt`: Unix timestamp (ms).

----------------------------------------------------------------------
8. DATABASE RELATIONSHIPS
----------------------------------------------------------------------
- `suppliers.id` -> `purchases.supplierId` (1:N)
- `suppliers.id` -> `supplierPayments.supplierId` (1:N)
- `purchases.items[].productId` -> `products.id` (N:1)

----------------------------------------------------------------------
9. CREATE / UPDATE / DELETE OPERATIONS
----------------------------------------------------------------------
- CREATE (Purchase):
  - Atomically writes to `purchases`.
  - Mutates `products` (increments stock).
  - Mutates `suppliers` (increments balance and totalPurchased).
  - Writes to `supplierPayments` if `paidAmount > 0`.
- CREATE (Supplier Payment):
  - Writes to `supplierPayments`.
  - Mutates `suppliers` (decrements balance, increments totalPaid).
- DELETE (Supplier):
  - Purges supplier from `suppliers`. Past purchases retain historical snapshot.

----------------------------------------------------------------------
10. BUSINESS LOGIC
----------------------------------------------------------------------
- Zero-Balance Payment Lock: Prevents operators from making accidental payments
  to vendors who are already fully paid, protecting the business from negative
  debt balances and phantom cash disbursements.
- Overpayment Prevention: An operator cannot disburse 50,000 PKR to a vendor who
  is only owed 20,000 PKR.
- Stock Synchronization: Receiving a shipment immediately updates available
  counter inventory so cashiers can begin billing the items.

----------------------------------------------------------------------
11. CALCULATIONS
----------------------------------------------------------------------
- Purchase Receiving:
  $$\text{Purchase Total} = \sum (\text{Line Quantity} \times \text{Cost Price})$$
  $$\text{New Supplier Balance} = \text{Current Balance} + (\text{Purchase Total} - \text{Paid Amount})$$
  $$\text{New TotalPurchased} = \text{Current TotalPurchased} + \text{Purchase Total}$$
  $$\text{New TotalPaid} = \text{Current TotalPaid} + \text{Paid Amount}$$
- Supplier Payment Disbursement:
  $$\text{New Balance} = \text{Current Balance} - \text{Payment Amount}$$
  $$\text{New TotalPaid} = \text{Current TotalPaid} + \text{Payment Amount}$$
